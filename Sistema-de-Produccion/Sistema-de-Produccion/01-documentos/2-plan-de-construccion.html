Ficha de contexto · v2

Eliges base de datos. Las APIs ya tienen su lugar.

Esta es la pieza operativa: la llenas al iniciar cada proyecto y me la pasas junto con la base. Ahora incluye el motor de datos, los conectores de API y los espacios de variables — sin secretos reales adentro.

contexto.proyecto.yml
# ── IDENTIDAD ─────────────────────────
proyecto:   "Café Raíz — menú digital"
cliente:    "Café Raíz"
linea:      starter        # starter | pro
base:       menu-con-panel-admin

# ── BASE DE DATOS (tú eliges) ─────────
base_de_datos:
  motor:        supabase     # firebase | supabase | ninguno
  necesita_auth: true
  tablas:       [categorias, items, pedidos]
  acceso:       rls_por_rol  # reglas de seguridad

# ── APIs / CONECTORES (espacios listos) ─
apis:
  pagos:       wompi        # wompi | mercadopago | stripe | ninguno
  mensajeria:  whatsapp     # link | api | ninguno
  mapas:       google_maps
  analitica:   ga4
  correo:      resend       # notificaciones

# ── VARIABLES (solo nombres, sin valores) ─
env:
  - SUPABASE_URL
  - SUPABASE_ANON_KEY
  - WOMPI_PUBLIC_KEY
  - GA4_ID

# ── MARCA ─────────────────────────────
marca:
  primario:   "#1F6B4A"
  secundario: "#F3ECE0"
  tipografia: "Fraunces + Inter"
  tono:       "cercano, artesanal"

# ── ENTREGA ───────────────────────────
entrega:
  dominio:   "caferaiz.co"
  hosting:   vercel
  idiomas:   [es, en]
  soporte:   plan_mensual

motor Base de datos a elección

Eliges Firebase o Supabase según el proyecto. La base técnica funciona igual con cualquiera porque la capa de datos (E5) tiene un adaptador para cada uno.

apis Conectores con su lugar

Cada integración tiene su campo. Si un proyecto no usa pagos, va ninguno. Nunca improvisas dónde meter la API: ya está previsto.

env Variables, no secretos

Aquí solo van los nombres de las claves. Los valores reales viven en el archivo .env del proyecto, fuera de la ficha y fuera de Git.

linea Una ficha, dos profundidades

El campo linea le dice a la base si activar el núcleo Starter o la extensión Pro. Mismo motor, alcance distinto.

Flujo por proyecto

Cómo iniciaremos cada trabajo.

Una vez el sistema esté armado, todo proyecto nuevo sigue estos cuatro pasos. Esto es lo que te ahorra horas en cada arranque.

PASO 1

Brief → Ficha

Tomas el brief del cliente y lo conviertes en la ficha de contexto: línea, base, base de datos y APIs.

PASO 2

Ficha + Base → yo

Me pasas la ficha y eliges la base. Yo ensamblo el producto configurado respetando la estructura.

PASO 3

Conectar datos

Pones tus claves en el .env. El adaptador conecta Firebase o Supabase sin tocar el resto.

PASO 4

Revisar y entregar

Ajuste fino de diseño, revisión de calidad y deploy. Queda listo para soporte mensual.

El plan está trazado. Empecemos por la Fase 0 o saltemos a la base estrella.

Mi recomendación: arrancar la Fase 1 con el menú con panel admin, porque construirlo nos obliga a dejar listos los fundamentos de paso.
