Cómo funciona

El contexto es la materia prima.

Cada base no se construye de cero: se alimenta con una ficha de contexto. Tú llenas la ficha, me la pasas junto con la base, y el producto sale configurado para ese cliente específico.

01

Defines el contexto

Respondes una ficha corta por tipo de proyecto: marca, rubro, paleta, secciones, integraciones y tono.

02

Eliges la base

Tomas la base técnica que corresponde —menú, carrito, landing— ya con su lógica resuelta y escalable.

03

Se ensambla

Contexto + base = producto configurado. Se respeta la estructura sólida, solo cambia lo que el cliente necesita.

04

Entregas y mantienes

El mismo sistema deja todo listo para soporte mensual: una fuente de ingreso recurrente.

contexto.menu.yml
# Ficha de contexto — Menú digital
cliente: "Café Raíz"
rubro: cafetería
base: menu-qr-panel-admin
marca:
  primario: "#1F6B4A"
  secundario: "#F3ECE0"
  tipografia: "Fraunces + Inter"
categorias: [café, brunch, postres]
integraciones:
  - whatsapp_pedidos
  - instagram_feed
panel: true     # el cliente edita solo
idiomas: [es, en]
tono: "cercano, artesanal"
Modelo de negocio

Dos líneas, dos promesas distintas.

El mismo motor sirve a un negocio de barrio y a una empresa mediana. Lo que cambia es el alcance, la profundidad técnica y el precio. Cada base indica hasta dónde escala.

● Línea Starter

Pequeños negocios

Cafés, bares, locales, emprendedores, freelancers. Necesitan estar online ya, simple y bien hecho.

  • Velocidad de entrega: días, no meses
  • Bases livianas, una sola sucursal/escenario
  • Precio de entrada accesible + plan de soporte
  • Foco en convertir: contacto, WhatsApp, reserva
// pago único + mantenimiento mensual opcional
● Línea Pro

Empresas medianas

Marcas con catálogo, varias sedes o equipo interno. Necesitan plataforma, datos y administración.

  • Paneles de administración y roles de usuario
  • Multisucursal, inventario, analítica integrada
  • Proceso con UX research y documentación
  • Contrato por fases + retainer de evolución
// proyecto por fases + soporte y mejora continua

Fundamentos

Buenas prácticas escalables.

Estas reglas son las que hacen que una base sea de verdad reutilizable y crezca de freelance a equipo. Aplican a todos los productos por igual.

01 Separa datos de presentación

El contenido (menú, productos, textos) vive en un archivo de datos o tabla, nunca incrustado en el HTML. Así el mismo diseño sirve para cualquier cliente cambiando solo la fuente de datos. Es la base de todo el sistema de contexto.

02 Design tokens, no valores sueltos

Colores, tipografías y espacios se definen como variables (CSS custom properties) en un solo lugar. Cambiar la marca de un proyecto es cambiar 6 variables, no buscar y reemplazar en 40 archivos.

03 Componentes, no páginas

Piensa en bloques reutilizables (hero, card, carrito, nav) que se combinan. Un componente bien hecho se usa en menús, landings y ecommerce sin reescribirlo. Construyes una vez, cobras muchas.

04 Estructura de carpetas fija

Cada proyecto usa la misma organización (/data, /components, /assets, /styles). Cuando entre otra persona al equipo, sabe dónde está todo sin preguntarte. La consistencia es lo que permite delegar.

05 Reglas de seguridad desde el día uno

En Firebase y Supabase, configura las reglas de acceso (RLS) antes de subir datos reales. Nunca dejes una base abierta. Un panel admin sin reglas es una filtración esperando a ocurrir.

06 Performance como estándar

Imágenes optimizadas, carga diferida (lazy load) y lo mínimo de JavaScript. Un menú que carga en 1 segundo se ve más profesional que uno bonito que tarda 6. La velocidad es parte del diseño.

07 SEO y analytics de entrada

Metadatos, títulos correctos y Google Analytics conectado antes de entregar. Le das al cliente datos desde el primer día y a ti un argumento para vender el plan de crecimiento.

08 Versiona con Git

Cada proyecto en su repositorio. Te permite volver atrás, trabajar en paralelo con otra persona y tener un historial. Sin Git no hay equipo, solo carpetas con nombres como "final_final_v3".

09 Documenta el contexto

Cada proyecto guarda su ficha de contexto (el YAML). Es el manual para mantenerlo, el punto de partida si lo replicas, y lo que permite que otra persona lo retome sin ti presente.

10 Accesibilidad mínima garantizada

Contraste suficiente, foco visible por teclado y textos alternativos. No es opcional: amplía el público del cliente y eleva la percepción de calidad de tu trabajo.

11 Pensar en mantenimiento = ingreso

Construye cada base sabiendo que tú la vas a mantener. Lo limpio y documentado hoy es el plan mensual rentable de mañana, en vez de un dolor de cabeza no cobrado.

12 Una base, dos profundidades

Diseña cada base con un núcleo Starter y una extensión Pro. No mantienes dos productos: mantienes uno que escala según el cliente. Menos código, más oferta.
